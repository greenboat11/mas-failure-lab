# Citation, license proposal and dataset releases

## Verified citation metadata

`CITATION.cff` uses the title from README, the origin repository URL and the Git author/account identifier greenboat11. The account is represented as a named entity; no personal name, affiliation, ORCID, DOI or paper is inferred. Version/date-released are omitted until a release is selected. The file uses JSON syntax, a YAML-compatible representation of [Citation File Format](https://citation-file-format.github.io/). Record the exact source commit and dataset version when citing a study; the framework title alone is insufficient for reproducibility.

## License recommendation, pending decision

I recommend **MIT** for the software: it permits broad reuse/modification with retention of its copyright and permission notice, which fits a small research framework intended for experiments and extensions. See the [official SPDX text](https://spdx.org/licenses/MIT.html). This recommendation does not adopt the license. No LICENSE file or package license field has been added, and the CFF makes no license assertion. Confirm the rights holder and desired terms before adoption. Dataset distribution terms should be selected explicitly as well, especially for future provider-generated traces; they are not automatically determined by a software recommendation.

## Future datasets

Keep existing small worked examples, their manifests and fingerprints in Git unchanged. Large future sweeps should be separate immutable versioned release assets, with a small catalog entry in Git containing dataset version, source commit, config hashes, seed scheme, trial design, schema versions, checksums, run counts, failure/censoring counts and limitations. Never silently replace an asset under the same version. Corrections require a new version with a changelog and linkage to superseded data.

`python -m mas_failure_lab.datasets` prepares a local ZIP plus SHA-256 sidecar from one completed output directory. It verifies recorded artifact hashes first and includes a DATASET.json inventory with per-file hashes and the original run manifest. It streams files into a fixed-order archive with fixed ZIP timestamps, preserving generated bytes. Packaging does not publish a GitHub release, push a branch, mint a DOI, or grant a license.

Example after running a local sweep:

```powershell
python -m mas_failure_lab.datasets --input results/local-stage3-oversight --version oversight-demo-v1 --output .tmp/releases/oversight-demo-v1.zip
```

Before any separately approved external release, review the inventory and verify the archive/sidecar; record model settings, reported usage, failures and incomplete trials; exclude credentials and private source material; choose dataset terms; then upload assets to a deliberately named release. A future archival DOI can be added only after it exists. This task leaves all external publication pending the owner's decision.
