# Analytical and limiting-case benchmarks

For the intact fixed scripted workflow, declared-label authorization discloses with probability **1 - p^(r+2)**. There are r+2 label-retention gates: the transformer, r relays, and the publisher. The two input labels are combined before the transform gate; there are not independent per-input gates. Label loss is irreversible, draws are independently keyed by stage under the model's pseudorandom scheme, every role continues, the payload is an exact canary and no component/handoff is removed. Thus publication is blocked iff all r+2 gates retain the label. Partitioning changes coalition requirements but not this formula.

The formula does not apply to sanitization, alternative routes, abstaining policies, or other authorization rules. Boundary p=0/1 checks are exact; interior agreement is a Monte Carlo check with a declared tolerance, not exact empirical equality. Additional routes can alter disclosure probability and minimum coalitions without breaking the baseline.

Oversight uses a discrete-time FIFO batch queue, not an M/M/1 queue. With one-tick eligibility, no retries and no queue removal, its request backlog satisfies Q_t=max(0,Q_(t-1)-C)+A_t. Stale requests still consume service, so deadlines do not change this recurrence. For constant original demand N hard tasks/tick, capacity zero gives Q_t=N(t+1); capacity >=N gives Q_t=N at every post-arrival snapshot. With no arrivals or all easy tasks the oracle baseline queues nothing. Unlimited review with one-tick latency and deadlines >=1 resolves hard tasks before deadlines, leaving only last-tick arrivals pending.

rho_0=N*arrival_probability*difficulty/C is nominal original offered load. It omits retries, false positive escalations and missed review needs. C=0 with positive demand is reported as null plus `infinite`; zero demand/zero capacity is null plus `undefined_zero_over_zero`. JSON never contains Infinity/NaN. The unlimited arm has infinite service capability and limiting rho_0=0; configured finite capacity is reported separately. No stationary-delay formula is asserted for finite horizons, deadlines or retry feedback.

A recurrence or limiting-case failure inside these assumptions is a potential implementation defect. Departures after introducing retries, uncertain review estimates, imperfect review, alternate routes or correction channels need mechanism-specific analysis. The original formula must not be imposed on a different model.
